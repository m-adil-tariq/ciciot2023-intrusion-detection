# Network Intrusion Detection on CICIoT2023 (Random Forest)

A Random Forest–based intrusion detection project on the CICIoT2023 IoT traffic dataset, designed as a direct methodological comparison to an earlier CICIDS2017 project — same model, same pipeline, different dataset.


Read Full Report here: [Report.pdf](./Report.pdf)

## Overview

This project trains a Random Forest classifier on an 8-class version of CICIoT2023 (Benign + 7 attack types: DDoS, DoS, Mirai, Recon, Spoofing, Web, Brute Force) generated by IoT devices attacking other IoT devices in a real testbed. The model and hyperparameters were held identical to the earlier CICIDS2017 project so that any differences in behavior could be attributed to the change in dataset rather than the modeling approach.

## Dataset

- **Source:** CICIoT2023 (Canadian Institute for Cybersecurity), using the derived 8-class single-file version by El Balbali & Abou El Kalam (2025)
- **Size:** 3,317,513 rows, 47 columns (46 numeric features + label)
- **Testbed:** 105 real IoT devices (cameras, speakers, sensors, Raspberry Pi nodes) acting as both attackers and targets
- **Classes:** Benign, BruteForce, DDoS, DoS, Mirai, Recon, Spoofing, Web
- Severe class imbalance: DDoS/DoS/Mirai make up >95% of records; Brute Force (900 rows) and Web (1,747 rows) are extremely rare

## Methodology

1. **Data loading & exploration** — cleaned columns, verified 8 distinct classes, mapped integer labels to readable names.
2. **Data cleaning** — checked for infinite/missing values (none found).
3. **Data preparation** — separated features/labels, confirmed all 46 features numeric, stratified 70/30 train/test split.
4. **Model training** — Random Forest (100 estimators, random_state=42), identical to the CICIDS2017 project for a controlled comparison.
5. **Evaluation** — precision, recall, F1-score, and confusion matrices, with attention to macro-averaged metrics given the imbalance.
6. **Feature importance analysis** — extracted from the deduplicated model.
7. **Cross-validation against literature** — compared findings to the original dataset paper and independent studies.

## Key Findings

- **Initial results** looked near-perfect in aggregate (weighted F1 ≈ 1.00), but macro-avg F1 was only 0.81, hinting at class-level problems.
- **Duplicate-leakage hypothesis tested and ruled out:** ~15.3% of rows (18.9% of DDoS rows) were exact duplicates. Removing them and retraining produced virtually no change in performance — confirming that DDoS/DoS/Mirai separability is genuine, not memorization.
- **Two clear weak classes:** Brute Force (recall 0.32) and Web (recall 0.24) — both had **zero duplicate rows**, ruling out leakage as the cause. Given their extremely small sample sizes (900 and 1,747 rows), the weakness is best attributed to **severe class scarcity**.
- **Confusion pattern is more distributed** than in the CICIDS2017 project: Brute Force, Web, Recon, and Spoofing frequently confuse with each other and with Benign, rather than concentrating in a single "normal traffic" bucket.
- **Feature importance reliance is fundamentally different:** a single feature, **Inter-Arrival Time (IAT)**, accounts for ~0.49 importance — about 10x the next feature — versus CICIDS2017's more distributed reliance on packet-length statistics. This reflects the tightly-scripted, regular timing of automated flood attacks (DDoS/DoS/Mirai).
- **Findings independently corroborated** by the original CICIoT2023 paper (Neto et al., 2023) and subsequent literature, including IAT dominance and the same Brute Force / Web confusion pattern.

## Limitations & Future Work

- Uses a random (stratified) train/test split; near-duplicate (non-identical) rows from the same session were not addressed. A temporal or session-based split would give a stronger evaluation.
- Brute Force and Web's poor recall reflects a genuine data scarcity problem, not a fixable modeling error. Future work could test SMOTE, other oversampling techniques, or class-weighted training.
- CICIoT2023's attacks were generated by automated, scripted tools in a controlled testbed, which may produce more consistent signatures than real-world attack traffic.
